1.1.1 变更摘要（改名批次，2026-11-17）
------------------------------------------------
本版只改名字，图标、便签内容、功能、界面样式全部未动：

 1) 产品名统一为 X Notes
    原来窗口标题栏写「便签管理」、主界面左上角写「桌面便签」，
    tauri.conf.json 的 productName 与安装包名又是 StickyNotes，三处不一致。
    现在统一成 X Notes：
      - 窗口标题（tauri.conf.json app.windows[0].title）
      - 页面标题（index.html <title>）
      - 主界面左上角品牌（Manager.tsx .brand）
      - 托盘 tooltip 与托盘菜单（tray.rs）
      - 单实例提示 MessageBox
      - 设置页标题由其父窗口标题提供，随窗口标题一起变
      - 关于页：当前版本还没有做（排在 1.2），本次不新增页面
    只改文字，未改任何布局、颜色、字号与图标。

 2) 配置与包名
    - tauri.conf.json：productName = "X Notes"，version = "1.1.1"
    - package.json：name = "x-notes"，version = "1.1.1"
      package-lock.json 顶层与 root 包同步为 x-notes / 1.1.1
    - Cargo.toml：包名 x-notes，库名 x_notes_lib，version = 1.1.1，
      description = "X Notes 便签工具"，authors = ["X Notes"]
    - main.rs 改调 x_notes_lib::run()
    - 单实例互斥体 Local\XNotes.SingleInstance.v1
    - 日志前缀 [x-notes]；export.rs 测试临时目录 x-notes-export-test-{}
    - 可执行文件：x-notes.exe（原 sticky-notes.exe）
    - 安装包：X Notes_1.1.1_x64-setup.exe（原 StickyNotes_1.1.0_x64-setup.exe）
    - 便携包：X Notes-1.1.1-portable.zip
    - 源码包：X Notes-1.1.1-source.zip

 3) 图标未动
    src-tauri/icons/ 下所有文件保持原样（32x32.png / 128x128.png /
    icon.ico 等），任务栏、托盘、安装包、卸载项继续使用原来的黄色便签图标。

 4) bundle.identifier 特意保留为 com.stickynotes.desktop
    改它会让 %APPDATA%\com.stickynotes.desktop 数据目录搬家，
    现有便签、分类、设置和图片都会"消失"（实际是留在旧目录）。
    本次只改显示名称，数据目录不动，老用户升级后便签原样可见。
    如果以后要彻底换标识，需要写一次数据迁移，留到后续版本。

 5) 兼容说明
    - 安装版：直接覆盖安装 X Notes_1.1.1_x64-setup.exe 即可，
      数据目录不变，便签不受影响。
    - 便携版：解压 X Notes-1.1.1-portable.zip 到新目录运行 x-notes.exe；
      旧的 sticky-notes.exe 可删除。数据同样在 %APPDATA% 里，不会丢。
    - 旧名残留只出现在历史文档（1.0.0 / 1.1.0 记录）与旧便携目录中，
      属于记录，不回改。

   - 缩到最小被压扁、左右两边被裁：原来实时缩放先把宽高分别夹到 80/60，

         真实比例把高度反算一次；images::fit_size() 的最小兜底从分别
         max(60)/max(40) 改成按比例放大。

1.1.0 维护批次（2026-11-17 晚，功能与缺陷修复）
------------------------------------------------
本批次只修缺陷与做清理，界面布局、颜色、尺寸未改：

 1) 全部隐藏后无法全部显示
    Ctrl+Alt+H 判断“是否有可见便签”时把回收站也算进来了（回收站里的便签
    visible 仍为 true），导致全部隐藏后再按一次永远走“隐藏”分支。
    现在只统计未删除的便签。

 2) 定位隐藏便签时不闪、不聚焦
    旧逻辑先建窗再立刻 emit_to("flash")，事件发在窗口创建之前被丢弃。
    现在定位时若窗口不存在，改为带 flash=1 建窗，由新窗口在页面加载完成后
    自己播 2 秒高亮，并在 show 之后聚焦；窗口已存在时仍走 emit_to。

 3) update_note 可绕过业务逻辑
    merge_patch 由黑名单（只挡 id / createdAt）改为白名单：只允许
    content / x / y / width / height / layer / backgroundColor / textColor /
    fontFamily / fontSize / bold / italic / textAlign / opacity /
    cornerRadius / shadow / border / frame / locked / clickThrough /
    lockAspect / category。deletedAt、visible、updatedAt、type、imageFile
    等只能走各自的命令，不再能绕过回收站与窗口销毁逻辑。

 4) 列表行“…”菜单关不掉
    全局 mousedown 关闭菜单时先关、按钮 onClick 又开，表现为点不动。
    现在 mousedown 排除“…”按钮本身，交给 onClick 做开关。

 5) 样式面板滑块偶发回跳
    90ms 防抖下可能有两次请求在途，旧响应晚到会覆盖新值。改为给每次请求
    编号，只有最新一次响应的结果写回界面，未发出的本地修改继续合并。

 6) 托盘进设置残留批量状态
    open-settings 事件先退出批量并清空选中，再切到设置页。

 7) 管理窗口尺寸上限不一致
    保存时上限写的是 4000，读取时 sanitize 钳到 2000，两者统一为 2000。

 8) “应用阴影到全部”计数偏大、列表重排
    改为只统计并广播未删除的便签，纯样式操作不再修改 updatedAt，
    列表按更新时间排序不会因为换阴影而跳动。

 9) 清理
    - 删除 0 引用的 CSS 变量：--panel / --line / --radius / --row-bg /
      --glass-bg / --glass-strong / --glass-weak / --glass-line /
      --glass-edge / --glass-shadow / --glass-shadow-soft。
    - 删除从未读写的 Note.monitor 与未使用的 Settings.data_version
      （旧 JSON 里的多余字段由 serde 忽略，notes.json 的 dataVersion: 2 保留）。
    - 修复 Cargo.toml 注释里的乱码字符。
    - README 精简为使用 / 构建 / 数据 / 结构 / 测试 / 限制，详细更新记录
      移到 docs/CHANGELOG.md，并把产物路径更新到 1.1.0。


1.1.0 维护批次 · 第二批（2026-11-17 晚，性能与体验）
------------------------------------------------
 1) 列表缩略图（read_thumbnail）
    新增 read_thumbnail 命令：Rust 侧把图片缩到最长边 144px、编码成 PNG
    data URL 再回传，并按“文件名 + 文件修改时间”缓存（超过 512 条清空）。
    管理列表的 .thumb 不再每次把整张原图 base64 到前端；便签本体仍用原图。
    解码前先克隆 images_dir、不持存储锁；文件名沿用 safe_image_path 校验。
    新增单测 thumbnail_shrinks_and_is_cached / thumbnail_rejects_path_escape。

 2) 管理窗口隐藏时跳过刷新、显示时补一次
    管理窗口不可见时，notes-changed 只置标记不刷新列表；
    visibilitychange 回到 visible 时补拉一次并清标记。
    分类 / 设置广播保持原样（低频轻量）。

环境注意事项
------------------------------------------------
1) 若把本程序放在 D:\Desktop\DSH_Test 这条路径下运行，exe 会因目录继承了
   Low 完整性标签而在启动时崩溃（0xc0000409，WebView2 报 0x800700AA
   "请求的资源在使用中"）。这是目录 ACL 问题，与程序本身无关。修复方式：

     icacls <目录> /grant "<用户名>:(OI)(CI)F" /T /C
     icacls <目录> /setintegritylevel Medium /T /C

   单独执行 /setintegritylevel 会报 Access is denied，必须先 grant。
   重新构建产物后建议再执行一次。
2) debug 模式跑 Rust lib 测试会因缺少运行期入口点崩溃（0xc0000139），
   请统一使用 --release。
